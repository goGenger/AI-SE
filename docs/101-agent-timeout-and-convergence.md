# Agent 超时语义与收敛 — 超时不再伪装成"结果格式错误"

> 来源：真实使用中「失败工作流重试」后 T2 仍失败，失败原因显示
> 「Professional Agent returned an invalid structured result.」
> 本修复只做 Agent 运行结果语义（超时 / 空回复的如实报告）、预算配置化与收敛提示词，不改 Workflow Engine / 任务判定策略。
> 编号说明：本文件取 docs 下一个空号 101（99 = 任务书、100 = 失败工作流重试记录），未覆盖任何既有文档。

## 侦察结论（真实数据，2026-09-28）

失败 run `51ba983a`（T2，workflow `9ed0eb96`，项目「画个自行车」，11:29:00–11:32:43，共 223s）：

| 时刻     | 事件                                            | 证据                                                                                                                       |
| -------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 11:29:00 | 主运行开始                                      | 24 次迭代：`run_unit_test`×21（5 失败）、`run_build`×6、`git_status`×3（全失败）                                           |
| 11:31:00 | `agent_run_finished: timed_out / TIMEOUT_ERROR` | **正好 120s**（`task.input.execution` 为空 → 默认 `timeoutMs: 120_000`）                                                   |
| 11:31:00 | 修复轮自动启动                                  | 主运行中止 → 空答案 → 旧逻辑判 INVALID → 对着空答案再问一次 → 模型把整个任务重做一遍（又 24 次迭代 / 103s）                |
| 11:32:43 | 修复轮结束                                      | 连续 3 次空回复（重问上限 2 用尽）→ 空最终答案 → `parseOutcome` 兜底 → 报「invalid structured result」（`answerLength=0`） |

三条问题：

1. **预算太小**：T2 的 `input.execution` 为空 → 走 120s 默认值；当天上午两次 `timed_out` 同因。
2. **超时后行为错误**：中止 → 空答案 → 触发无意义的"修复轮"（对着空答案重问），白烧 ~100s，并把真实原因（超时）掩盖成格式错误。
3. **Agent 不收敛**：任务本体只是"建 HTML 骨架"，却在自建验证脚本上反复跑 21 次单测，迟迟不输出结果 JSON。

## 修复

| #   | 层              | 文件                                                                           | 变更                                                                                                                                                                                                                                                                         |
| --- | --------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | agent-core 结果 | `professional/ProfessionalAgent.ts`                                            | 解析失败先分三类：**可解析优先**（交付了结果就不因时钟失败）；**超时** → 不启动修复轮，如实报「Agent 运行超时（Ns）」（`errorType: "TIMEOUT"`）；**连续空回复** → 如实报「Agent 未返回结果」（`errorType: "EMPTY_FINAL_ANSWER"`）；**有内容但不可解析** → 保留既有单次修复轮 |
| 2   | agent-core 图   | `graph/AgentGraph.ts`                                                          | `invokeLLMWithRetry`：**中止（超时 / 取消）后不再重试**，也不再发 `llm_retry` 事件                                                                                                                                                                                           |
| 3   | server 预算     | `config.ts` / `services/workflowTaskExecutor.ts` / `index.ts` / `.env.example` | 新增 `TASK_TIMEOUT_MS`（默认 **600000**，10 分钟）；任务输入 `execution.timeoutMs` 仍优先                                                                                                                                                                                    |
| 4   | agent-core 提示 | `professional/ProfessionalAgent.ts`（`RESULT_INSTRUCTIONS`）                   | 收敛规则：交付物达标即当轮返回结果 JSON；不建临时验证脚本、同一检查不重复超过两次；预算将尽时停止并如实返回结果                                                                                                                                                              |

## 边界与已知问题

1. 任务是否失败仍以 Agent 自报结果为准（docs/97）；本修复只让**失败原因可读**（超时 / 空回复不再伪装成格式错误）。
2. 迭代预算仍是 50（`maxIterations`）；超时与迭代预算都可能先到，两者分别如实报告（超时 → `TIMEOUT`；迭代耗尽 → 既有 `Agent reached max iterations`）。
3. 提示词收敛规则是行为引导，不保证模型一定收敛；真正的兜底是"预算 + 如实报告 + 人工重试"。
4. 工作区无 `.git` 时 `git_status` 仍会失败（噪声，不影响任务判定；docs/97 起工具失败不再推翻结果）。
5. 历史失败记录保持原样（不重写）。
