### F1-1 校验器缺输入时失败，不再静默跳过（发现②）

**问题**：N4 测试先行校验与 AC 覆盖检查只在任务带 acKeys 时生效；缺 acKeys 的计划（如 S1 v4）整体被跳过，等于没有保护。（核正：DEPLOY 交付块校验不受 acKeys 门控，见 §0 核正①。）

**方案**

1. 需求存在 AC 记录，而计划任务缺 acKeys → 校验失败，错误码 `PLAN_ACKEYS_MISSING`，进入修复流程；
2. 只有需求本身没有 AC 记录时才允许跳过，并在计划与事件中显式标注 `acProtection=none`。

（实施锚点：`validateTestFirstPlan.ts:50-76`、`validateAcceptanceCoverage.ts`；"有 AC 记录"的判定源取 N3 库记录、PRD 解析兜底。）

### F1-2 acKeys 确定性回填与单一生效计划版本（发现①、⑦）

**问题**：重规划后 acKeys 全空；旧版计划行与新版并存。二者同源：重规划产生新版本，但没有处理好 AC 映射和旧版本。（现场佐证见 §0 核正③。）

**方案**

1. acKeys 由代码依据 FR/AC 记录**确定性回填**（来源规则建议：切片 FR 范围 ∩ AC 记录，实施时以单测钉死），LLM 输出的 acKeys 只作参考；二者冲突以代码为准，并把差异写入事件；
2. acKeys 命名空间统一：已知的两种写法（含已修复的 `[FR-001]` 形式）都能解析，未知格式明确报错；
3. 同一切片任一时刻只有一个生效计划版本，旧版本行标记 `SUPERSEDED`，不参与调度、验证、追溯；**过滤下沉到仓储读取层默认生效**（需要旧版本的场景显式声明），避免逐点修补读取面遗漏。

（实施锚点：持久化 `planningRepositories.savePlanningResult / saveSlicePlanningResult / replaceSlicePlan`；`SUPERSEDED` 过滤在 `packages/database` 仓储读取层默认生效——运行时克隆（工作流创建/切片重启）、验证证据面（`taskVerifier` 的 `workflowTasks`）、追溯表（`traceability.ts`）随之继承过滤结果。）

### F1-3 校验错误的确定性自动修复（发现③）

**问题**：slice-2 的三次 LLM 修复：第 2 轮对第 1 轮的 5 个错误零修复，第 3 轮修掉大部分却引入新的 DEPLOY 交付块错误；任务数在 17→15→17 间漂移。这些错误全是机械性的。

**方案**

1. 在 LLM 修复循环**之前**增加确定性自动修复层，规则白名单：
   - **测试先行依赖**：对每个报错的（实现任务，测试任务）对，在不产生环的前提下补一条依赖边；
   - **DEPLOY 交付块缺失**：由平台依据项目交付配置补全——**仅针对最终切片的 DEPLOY 任务**（来源：项目仓库绑定 + `deployment_environments` 记录 + 平台 CI/Docker 配置；块仅需 action + environment）。非最终切片出现交付链任务时**不补块**，按 F1-4 的归属规则拦截（`DELIVERY_TASK_OUTSIDE_FINAL_SLICE`）；环境记录的缺失检查**提前**到工作流创建/需求分析预检（见 FX-13），补块处仅兜底；
2. 自动修复只增加依赖边、补交付块字段，**不增删任务、不改 AC 映射**；每次修复写入事件 `PLAN_AUTOFIXED`（规则、对象、前后差异）；
3. 补边会成环时不自动修复，**事件中记录环路径**；走 LLM 修复；修复轮耗尽后，切片规划失败**升级为人工关口**而非终态失败（复用既有审批机制，不新建体系），允许只重试该切片的规划，不影响已完成的切片；
4. LLM 修复提示要求"除报错部分外保持计划不变"，并记录每轮错误数与任务数，用于统计收敛率（报告指标，不设门槛）。

### F1-4 全局性 AC 的归属规则

**问题**：AC-30（README、`npm test` 全量、测试命名）这类全局性要求被分配给 slice-1 的任务 T-08，该任务实际上需要整个应用存在才能完成，于是出现超范围实现、600s 超时和跨切片污染。

**方案**

1. **定义与归属规则**：
   - **全局性 AC**：验证方式为 Deploy 或 Doc 的 AC（E1 中为 AC-24、25、26、29、30）；
   - **交付链任务**（含 delivery 块的 BUILD/DEPLOY/VERIFY 交付类）**只允许出现在最终切片**；非最终切片的二级规划提示词不得以交付链收尾；二级规划校验按「是否最终切片」参数化（序号与总数取自库中 `slice_order`），新错误码 `DELIVERY_TASK_OUTSIDE_FINAL_SLICE`——不在自动修复白名单，走 LLM 修复/人工关口；（单级 `full` 模式不受此规则影响，维持计划尾部交付链。）
2. 规则：非最终切片的任务不得挂全局性 AC（新错误码 `GLOBAL_AC_OUTSIDE_FINAL_SLICE`）；这些 AC 归入最终集成切片的收尾任务。需要增量维护的内容（如 README 的当前切片部分）按切片拆分，最终汇总；
3. **防止最终切片过重（「超限再拆」：observe 先行、校准后 enforce）**：
   - **observe 阶段**（F-M1 期间，默认）：记录最终切片规模（任务数 / 交付链任务数 / FR 数 / 全局性 AC 数）并发事件，**不判失败**；L1 阶段同步预检（按 FR 数 + 全局性 AC 数预估），把发现提前到规划期，而不是执行完前四个切片之后；
   - **校准**：以 L2 的 3 次实测校准阈值；enforce 初始值**不低于 18**（高于已观测的 17：slice-2 三轮计划任务数为 17/15/17），随校准写入 `docs/129`；
   - **enforce（开关默认关，校准后另行开启）**：校验点 = 二级（切片级）任务计划校验（错误码 `FINAL_SLICE_OVERLOAD`）；超限 → ① LLM 压缩（提示：不增删 AC 映射）→ ② 仍超限：**一级重做拆分**（仿 `redoLevel1`），将最终切片拆为「工程契约」「部署验证」两个切片（E1 即 5→6 切片），经关口 1 审批——**拆分只作用于尚未开始的最终切片**：已完成切片的 FR 范围、任务与计划行原样保留，不得标记 `SUPERSEDED`（含回归断言）→ ③ 再失败 → 人工关口（与 F1-3 同一升级路径）；
   - **关口 1 复核**：一级重做会再次经过关口 1 审批；评测 harness 须处理该情形并如实计入人工介入次数（FX-15(d)）；
4. 规则由代码校验，不依赖 LLM 自觉。

（实施锚点：task-planning 提示词按「是否最终切片」切变体（先例：`task-planning.prompt.ts` 的 `deliveryConfigured` 条件化）；校验器与自动修复层同参；「是否最终切片」由 `planningService.planSlice` 依据 `requirement_slices.slice_order` 与切片总数传入。）

### F1-8 指标口径与历史重算

**问题**：E-1 run-1 的"真成功"是 oracle 通过但链中断；所有 E1 批次的自报成功均为 0，使"假阳性 0/3"没有证明力。

**方案**：harness 新增并冻结以下口径：

| 指标               | 定义                                                          |
| ------------------ | ------------------------------------------------------------- |
| `chainCompleted`   | 所有切片均为 SUCCESS                                          |
| `deliveredSuccess` | `oraclePassed ∧ chainCompleted`（真交付成功）                 |
| `falseNegative`    | `oraclePassed ∧ ¬chainCompleted`，并标注是否存在超范围写入    |
| `sliceReached`     | 链到达的最远切片                                              |
| 任务级验证分歧     | 任务自报 SUCCESS 但验证 FAIL 的任务数（验证门的真实效果指标） |

**报告细分指标（F-M1 出口必列）**：上述全部 + 失败分布（按新错误码；按层：规划 / 验证门 / agent 级）+ 自动修复与 LLM 修复轮数分布、首轮通过率与收敛率。
