## 3. 任务明细

### G1 VACUOUS_TEST 判定精化（最高优先）

**现象与证据（三个真实案例）**：

- 案例 a（run2 slice-3；工作流 `0fa3089a`；任务 `9626ef98`「运行切片集成验证与回归测试」）：红灯期望（expected=fail）下套件全绿 → 判 VACUOUS×2；agent 自报为期望失配。
- 案例 b（run3 slice-2 重跑；工作流 `67781741`；任务 `51e20dc2`「TEST：登录、签名令牌、鉴权中间件与健康端点测试（AC-01/09/10/11/12/13）」）：44/44 全绿；实现已在工作区（重跑场景），红灯无法成立；agent 自报为任务编排/环境问题而非代码缺陷。
- 案例 c（run3 slice-4；工作流 `911c5327`；任务 `47d7c85d`「编写 AC-19 PATCH 严格字段校验测试」）：同类模式（vfc=VACUOUS_TEST×2）。

**机制定位（2026-10-14 代码勘察）**：`taskVerifier.resolveCheckOutcome` 的红灯翻转（E-0）要求「全部**解析** AC 均有**同工作流内**已成功 + 开发类任务的实现证据」；两处系统性假阳：

1. **跨切片 / 跨 run 证据缺口**：解析 AC 集含前序切片 AC（案例 a 的 AC-01..13 属 slice-1/2；案例 b 的 AC-01 属 slice-1），或实现来自前一 run 的工作区（案例 b）——同工作流证据面无法覆盖 → 误判空转；
2. **期望映射**：以「红灯期望」运行的集成/回归验证类任务在实现完备后天然全绿（案例 a），与「测试先行空转」语义混淆。

**方案方向（实施前先离线复现，后定稿）**：

- G1-1 翻转判定改用**作用域内 AC**（复用 F1-5 `scopedAcKeys` / result-filter 机制）；作用域外 AC 不参与证据要求；
- G1-2 证据面扩展：实现证据纳入「同需求**前序切片**工作流」与「同需求**前序 run** 的工作区/提交证据」；通道不可得时保持保守（fail-closed 不放松）；
- G1-3 期望映射复核：TEST 类任务的期望（红灯/绿灯）按任务语义细分（测试先行 vs 集成回归验证）；
- G1-4 真阳保持：无实现、自引用、无断言的测试仍判 VACUOUS（回归夹具覆盖）；
- G1-5 夹具与复测口径：三案例离线回放（先红后绿）；L4 复测目标 = **无 VACUOUS 链停归因**、判负数显著下降且无真阳漏判。

**验收（GX-01..05）**：三案例回放按预期翻转；真阳夹具仍判负；单测 + 全仓无新增失败。

### G2 规划精简（T5 其余）

- **现状**：完整规划管线 8 个串行 LLM 阶段（analyze → functional → technical → architecture → api → database → [ui] → taskPlan）；`skipStages` 机制已存在，当前仅二级 `ui_spec` 按 `involvesUi` 跳过（`planningService.ts:1070`）；F1-8 度量已就绪（首轮通过率 / 修复轮数 / 收敛；L4 数据见 §1）。

- **确定性跨规格一致性检查**（T5 原定验收项）：任务引用的 API 路径必须存在于 api 规格；DB 规格的表必须被至少一个任务使用；单测覆盖。

### G3 长任务超时策略

- **现象**：`TASK_TIMEOUT_MS = 600_000`（`apps/server/src/config.ts:38`）；「pnpm 工程骨架与脚本契约（零运行时依赖）」任务三 run 实测（§1）——边界性慢任务，一刀切超时。
- **调查项**：任务耗时分布（agent_runs 实测）、超时判定与重试语义、失败传播。
- **策略选项**：按任务类型/阶段缩放超时；进度感知延长；或任务粒度提示（骨架类任务拆分）。**约束**：不放松全局默认；如引入按类型覆盖需配置化 + 文档化 + 边界用例。
- **验收（GX-09..10）**：超时模拟夹具；E1 复测无同类链停归因。

### G4 链推进前序完整性

- **现象**：`advanceSliceChain` 取「首个 PENDING」切片（可跳过 FAILED）；run3 中 slice-1 成功后推进 slice-4（`911c5327`，19:02:54 = replan v34 后 +2m48s）与 harness 重启的 slice-2（`67781741`，19:00:09 = +3s）双链并行。
- **语义明确化选项**：(a) 严格前序（存在更早未完成切片时不推进；告警/挂起）；(b) 保留现状 + 事件记录 + 报告标注；(c) 推进目标 = 「下一个尚未 DONE 的切片」且要求其前序全部 DONE。
- **验收（GX-11..12）**：状态矩阵单测（DONE/FAILED/PENDING 组合）；与 harness 重启语义的交互文档化。
