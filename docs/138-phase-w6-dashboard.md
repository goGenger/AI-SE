## 二、首屏按「用户会问的问题」重排

计划 §W6 工作项 4 的顺序，逐条落地：

| 顺序 | 区块 | 内容 | 数据来源 |
| --- | --- | --- | --- |
| ① | **需要处理** | 失败 / 等待审批 / 已暂停，**状态色 + 数量** | `workflowsStore` |
| ② | **正在运行** | 运行中 / 等待中 | `workflowsStore` |
| ③ | **最近的动态** | 最近工作流（表格，最多 5 条） | `workflowsStore` |
| ④ | **总量统计** | 项目总数 / 启用中 / 已归档 | `projectsStore` |

### 两个刻意的设计决定

**数字的颜色只在非 0 时使用。** 「失败 0」标成红色会把平静的界面喊成告警。0 一律走中性灰，非 0 才用对应状态的语义色。

**「需要处理」全为 0 时不摆三个 0，换成一句平静的话**（带一枚绿色对勾）：「当前没有失败、等待审批或已暂停的工作流。」三个并排的灰色 0 传达不了「一切正常」。

### 口径（写进 viewmodel，不散在模板里）

```ts
关注 = FAILED + WAITING_APPROVAL + PAUSED
推进 = RUNNING + PENDING
```

`SUCCESS` / `CANCELLED` 两边都不属于，所以不计入任何一个数字。这四个导出（两个常量 + `countWorkflowsInStatus` + `latestWorkflows`）放在 `workflowsViewModel.ts`，并有 5 条单测锁住口径。

### 工作流三块的加载/错误只表达一次

①②③ 共享一个 store。若各自渲染状态，错误会重复三遍、加载会出现三个骨架屏，而「运行中 0」还会**假装**成「没有在跑」。因此三块之上只有一个 gate：加载 → 一处骨架屏；错误 → 一处 `ErrorState`（可重试）；否则正常渲染。

项目卡（④）有自己独立的四态 —— 它用的是另一个 store，错误不该互相牵连。

## 三、一处**内容变化**：最近项目 → 最近工作流（需要你确认）

改造前仪表盘的主体是一张「最近项目」表（列：项目 / 描述 / 状态 / 创建时间）。

按计划 §W6 工作项 4 的「③ 最近的动态」，我把它换成了「**最近工作流**」（列：需求 / 项目 / 状态 / 创建时间），理由是：

- ① 和 ② 都是工作流视角的。如果 ③ 突然回到项目视角，首屏会自相矛盾；
- 「动态」在一个工作流自动化控制台上应该是**在跑的/刚跑过的那些东西**，而不是「存在哪些项目」；
- 项目列表有独立页面，也在侧栏有独立入口。

**代价是仪表盘不再直接深链进项目详情。** 如果你更希望保留「最近项目」表，说一声，把它作为第 5 块加回来（或替换 ③）都是十几分钟的事。

**「无虚构数据」护栏**：原本的禁用词表里有「最近动态」——那条守的是「没有数据源却摆一个动态流」。现在数据源真实存在且可测，因此把该词从禁用表移除，其余 11 个词保留。这个改动在测试里有显式注释说明原因。

## 五、决策与偏离

### 决策 1 · 数据源：projects + workflows（用户裁决）

计划内部有一处**自相矛盾**，动手前已报告并请用户裁决：

- 工作项 5 说「指标口径必须来自真实数据（`projectsStore` **等现有 store**）」；
- 约束却说「业务数据与 **store 调用不变**」。

而按工作项 4 的优先级，① 和 ② **用项目数据根本推不出来**（项目只有 active/archived，没有「失败」「正在跑」）。

用户裁决：**projects + workflows**。关键事实是侧栏（`AppSidebar.vue`）**已经在全站加载 workflows**，所以本页读它**不增加任何实际请求** —— 本页只补一个「store 为空且未在加载」的兜底守卫，保证直接深链到 `/` 时也有数据。

### 决策 2 · 删除轨道而不是「去动画」

计划写的是「删除流程轨道（`.dashboard-rail`/`.dashboard-dot`）与入场动画」。轨道本身被删了，不是只去动画 —— 它承载的四个站名（项目/需求/工作流/部署）与侧栏完全重复。

### 决策 3 · 补 `PageHeader`（W5 骨架的一致性）

仪表盘是全站**唯一**没有 `<h1>` 的页面。W5 已把「页头区（标题 + 一句话说明 + 唯一主操作）」定为骨架第一段，仪表盘不该是例外。顺带解决了一个无障碍问题：页面原本没有一级标题。

这一条不在计划 §W6 的工作项里，属于「W5 骨架的收尾」，在此显式登记。

### 决策 4 · 保留「空项目」引导

项目卡在 `projects.length === 0` 时不摆三个 0，而是显示「还没有项目。」+「新建项目」（沿用改造前的引导文案）。一个项目都没有时，数字带给不出下一步。
