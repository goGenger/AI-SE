## 2. 自治 L2 的定义（**这是本文件要你先裁定的第一件事**）

目前关于 L2 的全部官方表述只有一句：**「关口 1 纳入即等于 L2」**（`docs/146` §4，2026-10-15）。
这句话没说「纳入」之后平台**做什么**。三种读法，代价与含义完全不同：

| 读法 | 含义 | 代价 | 风险 |
| --- | --- | --- | --- |
| **A. 仅纳入契约** | 关口 1 仍**无条件人工**，但它的决策写入自治决策事件、纳入验收与批次统计 | 低（事件 + 断言，无策略逻辑） | 门仍然是橡皮图章——**只把现状写成了合同**，不产生任何新判断 |
| **B. 阈值化（推荐）** | 平台用**确定性判据**检查切片计划：满足 ⇒ 自动批准并记决策事件；不满足 ⇒ **必须人工** | 中（一个纯函数判据 + 事件 + 断言 + 一次批次） | 需要先把判据设计对，否则「自动批准」会放行坏计划 |
| **C. 完全自动** | 关口 1 对 L2 一律自动批准，人工门只留生产与高风险 | 低 | **不建议**：范围设定是人唯一还握着的地方，全放开等于取消 L2 存在的理由 |

**推荐 B。** 理由不是「更高级」，而是**它同时修掉了 §1 里那个真实问题**：
现在 86 次批准全是人点的（或在评测里由 harness 代点的），而**没有一条记录说明凭什么批**。
按 B，每次批准要么带着「命中了哪几条判据」，要么就必须有人来点——
**橡皮图章被换成了一道可复核的检查**。

**B 的判据（推荐初值，四条全部满足才自动批准）**：

1. **FR 覆盖完整**：各切片 `fr_keys` 的并集 = 需求全部 FR，且无切片 `fr_keys` 为空
2. **范围可控**：切片数 ∈ [1, 5]，且每个切片的 FR 数 ≤ 3
3. **依赖健康**：`depends_on` 无环，且只指向 `slice_order` 更小的切片
4. **最终切片不超规模**：`frCount + globalAcCount` ≤ 阈值（复用既有 `FINAL_SLICE_SCALE_PREVIEW` 的估值口径，`planningService.ts:601-614`）

四条都是**纯函数、可单测、可回放**的判定，不引入第二套审批或第二个决策系统。

## 4. 任务明细

### L2-M1 回归门（零行为变更，只加断言）

**L2-1 关口 1 阻塞第二级（回归门）**
- **目标**：**生产链路中**，需求处于 `PLANNING_REVIEW` 且有 PENDING 审批时，**不产生任何第二级规划**。
- **改动**：**无生产代码**。补断言：置 `PLANNING_REVIEW` 后，`GET /api/requirements/:id/slices` 的
  PENDING 切片**不出现** task plan；批准后才出现。
- **落点**：`apps/server/src/__tests__/sliceFlow.e2e.test.ts`（既有两级规划用例）。
- **已知例外（必须写进断言注释）**：`planPendingSlicesInOrder`（`planningService.ts:1389-1398`）
  是 F 阶段的**规划演练入口**，设计上就绕过关口 1 且**不创建工作流**。
  本项**只约束生产链路**，不断言该入口——但也不得让它在本项的实施里被顺手改掉。

**L2-2 拒绝 → 重做有界（回归门）**
- **目标**：拒绝（带 comment）触发第一级重做并携带 `sliceFeedback`；**第 3 次拒绝**判需求 FAILED。
- **改动**：**无生产代码**。补断言：`redoLevel1` 被调用且带 comment；
  连续 3 次拒绝后需求状态为 `FAILED`，且**重做恰好 2 次**（无第 3 次）。
- **落点**：`apps/server/src/__tests__/sliceFlow.e2e.test.ts` + `planningService` 单测。

**L2-3 控制台入口（回归门）**
- **目标**：需求页在 `PLANNING_REVIEW` 时展示切片计划与批准/拒绝入口。
- **改动**：**无生产代码**（已实现）。补前端断言。
- **落点**：`apps/web/src/__tests__/`（既有 SSR 断言模式）。

### L2-M2 策略载体（零行为变更）

**L2-4 自治级别表达 L2**
- **改动**：`AutonomyLevelSchema` 由 `z.enum(["L1"])` 扩为 `z.enum(["L1","L2"])`；
  `policyId` 取级别名（沿用 L1 的约定）。
- **判据**：① 声明 `"L2"` 的旧 payload 原样通过；② **未声明时的行为与现状逐项一致**（全量门禁）；
  ③ 声明 L2 的工作流**继承 L1 的全部行为**（门强制、有界重试、自动回滚、四个决策事件）。
- **风险**：`WorkflowPolicySchema` 是 `.strict()`。枚举扩展是**向后兼容的放宽**，
  但须核实读取路径不做运行期校验（L1 实施时已核实过一次，`docs/154` §3 M2）。

### L2-M3 判据与决策事件

**L2-5 gate-1 判据（纯函数）**
- **改动**：新增一个**纯函数**（落 `packages/shared`——跨包契约的家，`AGENTS.md` §3）
  `evaluateSlicePlanGate(plan, requirement)` → `{ satisfied: boolean; reasons: string[] }`，
  逐条给出**未命中的判据名**（空数组＝全部满足）。判据内容见 §2（四条）。
- **判据**：单测覆盖每条判据的正例与反例；反例必须**指名**是哪一条没过。

**L2-6 自动批准与决策事件**
- **改动**：`persistSlicePlan` 在建 PENDING 审批之后，若工作流/需求所属策略为 L2 **且**判据全满足 ⇒
  自动批准（复用既有 approve 路径）并写**自治决策事件**；否则**保持 PENDING 等人工**。
- **事件**：新增 `GATE1_AUTO_APPROVED` 到 `AUTONOMY_DECISION_PAYLOAD_SCHEMAS`
  （payload：`policyId` / `requirementId` / `sliceCount` / `satisfiedReasons[]` / `estimatedFinalSliceTasks`）。
  **不能复用 `AUTO_APPROVED`**，有两条硬理由：① 它是 `z.literal("staging")`
  （`packages/shared/src/index.ts:1207-1214`），而关口 1 与部署环境无关；
  ② 它的公共字段**要求 `workflowRunId` 与 `taskId` 两个 uuid**
  （`:1191-1199`）——**关口 1 发生时这两者都还不存在**（切片计划是工作流的前置）。
  契约层面的类型不兼容，不是措辞问题。
- **判据**：E2E 两条——命中 ⇒ 审批立即 `APPROVED` + 事件落库且能按 `requirementId` 查到；
  任一不命中 ⇒ 审批保持 `PENDING`、**零** `GATE1_AUTO_APPROVED` 事件。
- **红线**：仍走既有 `approvals` 与 `createRequirementApproval`，**不新增第二套审批**。

### L2-M4 数据门槛

**L2-7 L2 策略下的批次**
- **目标**：① 一次 E1×3，三个 run 的 gate-1 判定**都被记录**（自动或人工，事件可查）；
  ② **staging 段 ≥ 2/3**（证明 L2 没有让 L1 的水平回退）。
- **改动**：
  1. 批次脚本声明 `autonomyLevel: "L2"`（新增脚本，结果目录另开，不续跑既有批次）。
  2. **离线回放先行（零配额）**：对现存 10 个需求的计划跑判据，输出「哪些会自动批 / 哪些会送人工」。
- **判据**：①② 均达成即达成；未达则如实记录 PASS-PARTIAL 并归因，不伪装。
- **⚠️ 样本量限制（必须写进记录）**：切片计划**不留历史**（`replaceSlicePlan` 先删后插），
  离线回放只能用**当前 10 份计划**，它**不能替代**批次——只能证明判据不崩、分布合理。

## 8. 红线（沿用 `docs/17` L1-9 与 `docs/154` §7）

- **生产与高风险的人工门不可由策略关闭**；L2 只在**切片计划**这一处增加了平台判定权。
- **Tool Runtime 是唯一执行路径**；不新增第二套 Permission / Approval / Audit / 错误码体系——
  自动批准**必须**复用既有 `approvals` 表与批准路径。
- 明文 credential / token 不进 Prompt、State、Task、Log、Result；事件 `reason` 落库前走
  `@ai-se/observability` 的既有 sanitize。
- 观测与决策记录**只增不改**：不改既有事件类型与既有 payload 形状。
- **L2 ⊇ L1**：不得因引入 L2 而回退 L1-1 … L1-9 的任何一条。
- 不修改任何 `dist/`；不做运行期重启实验。
