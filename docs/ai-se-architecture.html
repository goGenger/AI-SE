AI-SE 平台 · 架构与工作流

as-built（以仓库代码为准）· 13 packages + apps/server + apps/web · 2026-09-28 · C/D 增补 2026-10-08

① 系统架构 — 分层：控制台 → HTTP API → 应用服务 → 工作流引擎 → Agent 运行时 → 工具与治理 → 沙箱 → 数据 / 外部系统
② 工作流生命周期 — 规划 → 调度 → 领取 → 执行 → 判定 → 失败策略 / 交付链；右侧为控制面与人工入口
③ 单次 Agent Run 内循环 — 一次任务的执行细节：LLM ⇄ 工具循环 → 最终答案 → 结果解析管线
④ C/D 阶段加固能力 — 验证门 / submit_result / AC 追溯 / 脱敏 / API Token / 交付链演练（2026-10-08 增补）

分层职责（谁管什么）

  • Workflow Engine：业务生命周期唯一编排者 —— 需求→规格→任务图、依赖与并行、重试/失败恢复、动态任务、重规划、审批/暂停/恢复/取消、交付编排。
  • Agent Runtime（LangGraph）：只负责单次 Agent Run —— 状态、模型调用、工具循环、条件路由、checkpoint；禁止把业务生命周期做成一个大 LangGraph。
  • 应用服务层：规划、工作流、交付、运行时/治理四组服务；HTTP 路由薄，业务逻辑集中于此。
  • 控制台：api（fetch）→ stores（Pinia）→ viewmodels（可测纯逻辑）→ views（11 页，一页一文件）。

架构不变量（红线）

  • Tool Runtime 是唯一执行路径：Agent / MCP / MCP Apps 均不得绕过。
  • 所有代码执行必须经 Sandbox（工作区白名单 + 容器内执行）。
  • 禁止第二套 Permission / Approval / Audit / Secret / 错误码体系。
  • Workflow 必须可恢复、可取消；授权验证须证明"无过期授权"。
  • 凭据零明文：不进入 Prompt / State / Task / Log / Result；日志走 observability 脱敏。
  • Agent 不直接访问外部系统（LLM 之外的 GitHub / Docker / MCP 一律经适配器）。

数据与外部依赖

  • PostgreSQL 16：全部业务实体与执行留痕（workflow / task / agent_run / tool_call / artifact / evidence / approval / deployment / mcp / planning）+ SQL migrations。
  • Redis 7：唯一职责 = 跨进程取消（agent-run:<id>:cancel，1h TTL，250ms 轮询）+ 健康检查；与 PostgreSQL 无重叠（G5/T9 审计）。
  • LLM：DeepSeek / OpenAI 兼容（思考模型 · token 与成本计量）。
  • 交付：LocalCi / GitHubActions + Docker（镜像构建 → staging → 生产审批）。
  • MCP：stdio + remote 两种传输，契约冻结（docs/25）。
